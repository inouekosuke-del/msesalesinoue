# 朝礼ボード データ層の診断・修復ツール

[`docs/chorei-board-audit-2026-09-13.md`](../../docs/chorei-board-audit-2026-09-13.md) で
検出した不具合のうち、**データ側だけで直せるものを直す**ための追加スクリプト。

アプリ本体には触らない。関数名も日本語なので既存の関数と衝突しない。
シートは名前ではなくヘッダー行の組み合わせで特定するので、シート名が変わっても動く。

| ファイル | 役割 |
|---|---|
| `ChoreiFix.gs` | 診断と修復 |
| `ChoreiAgg.gs` | 「正しい集計」の参照実装。画面の数字と突き合わせる対照表を作る |
| `test/` | GASをスタブしてNodeで流す回帰テスト |

## 手順

### 1. 追加する

朝礼ボードのスプレッドシート → **拡張機能 > Apps Script**。
`ChoreiFix.gs` と `ChoreiAgg.gs` を新規ファイルとして貼る。

### 2. 診断する（読み取りのみ）

`診断()` を実行。`_診断レポート` シートに出る。2026-09-13 のデータでの結果:

| 区分 | 項目 | 件数 |
|---|---|---:|
| 取り込み | 1回で2ファイル以上を処理した日 | **4日**（9/10・9/11・9/12 は案件が約2倍） |
| 取り込み | 中身まで同一の重複行 | 6 |
| 月キー | 日付セルになっている月キー | **9,440**（= 全行×2列） |
| 名寄せ | 案件の `ownerId` が空 | 134行 / **￥119,059,295** |
| 名寄せ | 日次履歴の `memberId` が空 | 213行 |
| キー | `lineId` の衝突（別案件が同一キー） | 172キー |
| キー | `oppId` が空 | 4,720 / 4,720行 |
| 目標 | members と 月別目標 の食い違い | 3件 |
| 目標 | 月別目標に行が無い在籍メンバー | 8名 |
| TODO | `todoTitle` が埋まっている行 | 0 / 2,042 |
| 指示 | 完了済みなのに `active=TRUE` | 10 / 12 |

### 3. 名寄せできない担当を登録する

`メンバー追加候補()` を実行。`メンバー` シートに貼れる行がログに出る。
吉牟田さん・小菅さんは Slack ID まで埋まる。**追加してから修復に進むこと。**

退職・異動済みなら `active` を `FALSE` に。過去分の名寄せは `active` に関係なく効く。
`API Integration` はシステムアカウントなので、名寄せ対象から自動で外れる。

### 4. 修復する

```
修復_ドライラン()   ← 何をどう変えるかだけ出す。書き込みなし
修復_実行()         ← バックアップを作ってから適用する
```

直すのは2種類:

| 直すもの | 規模 | やり方 |
|---|---:|---|
| 月キー列（日付型 → テキスト） | 9,440セル | 列を `setNumberFormat('@')` にしてから `setValues()` で一括 |
| 担当者の名寄せ（`ownerId` / `memberId`） | 481セル | セル単位 |

**月キーはセル単位で直しても直らない。** 文字列を書いてもGoogleスプレッドシートが
また日付に変換するため、先に列をテキスト書式にする必要がある。
そのため書き込みは列ごとの一括（`setValues` 2回）で行う。
9,440セルをセル単位で書くと実行時間を使い切る。

`修復_実行()` は最初に `DriveApp.makeCopy()` でスプレッドシート全体のコピーを作る。
URLは実行ログに出る。行の削除はしない。何度実行しても結果は同じ（冪等）。

### 5. 数字を突き合わせる

`検算_今月()` → `_集計検算` シートに担当者別の受注／計上見込みが出る。
**これと画面の数字が合わなければ、画面側の集計が間違っている。**

`ChoreiAgg.gs` が守っている4つの約束:

1. **`side` を必ず指定する** — 案件は受注行と計上行の2行ある。省くと必ず倍になる
2. **月キーは `toMonthKey_()` を通す** — Dateでも文字列でも同じ結果になる
3. **担当は名寄せしてから集計する** — `ownerId` が空でも `ownerName` から引き直す
4. **知らない進捗は捨てずに返す** — `unknownStages` に出る。SFに進捗が増えても静かに消えない

## このツールで直らないもの

| 不具合 | 直す場所 |
|---|---|
| 二重取り込み（`files=2` の日に倍になる） | 朝礼ボードのGAS本体（取り込み処理） |
| `oppId` が全行空 / TODOの件名・状況が空 | Salesforceレポートの取得列 |
| 完了した指示が再表示される | GAS本体 |
| クリックで先頭にスクロールする | 本体のHTML/JS |

**`active` を落とす修復は入れていない。** 本体が `active` をどう使っているか
分からないまま落とすと、指示が画面から消える方向に壊れるため。

## 取り込み側を直すとき

`toMonthKey_()` / `safeDate_()` / `normName_()` / `memberIndex_()` /
`isNonMemberOwner_()` は `ChoreiFix.gs` に単独で完結する形で置いてある。
本体の取り込み処理からそのまま呼べる。そうすれば以後は修復が要らなくなる。
