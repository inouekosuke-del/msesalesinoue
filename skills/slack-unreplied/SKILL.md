# slack-unreplied（Slack未返信一覧）

自分が投げたきり相手から反応が返っていないメッセージを拾い、催促漏れを防ぐためのskill。

**このskillが答える問い** … 「自分が最後に喋ったまま止まっている会話はどれか」
**見ないもの** … 相手から来ていて自分が返していないもの（＝自分のTODO）。それは別物なので混ぜない。

---

## 定数

| 項目 | 値 |
|---|---|
| 自分のSlack user_id | `U06RQRBKM0F` |
| 自分宛DM（結果の投稿先 / 自分用メモ） | `D06S2EVR5GV` |
| 遡及期間 | 3日（実行日を含む。`after:` は実行日-3日） |
| タイムゾーン | JST |

`D06S2EVR5GV` は自分専用のメモ用DMで、参加者が自分ひとりのため構造上ぜったいに返信が来ない。
**検出対象からは必ず除外**し、投稿先としてのみ使う。

---

## 実行手順

### Step 1: 期間を確定
実行日を `TODAY`（JST）とし、`AFTER = TODAY - 3日` を `YYYY-MM-DD` で求める。

### Step 2: 自分の発言を全部集める
```
slack_search_public_and_private(
  query = "from:<@U06RQRBKM0F> after:{AFTER}",
  sort = "timestamp", sort_dir = "desc",
  limit = 20, include_context = false,
  channel_types = "public_channel,private_channel,mpim,im"
)
```
`pagination_info` のカーソルが尽きるまで**全ページ辿る**。途中で打ち切ると、古い会話＝いちばん催促すべき会話が落ちる。

各件から `channel_id` / `channel_name` / `message_ts` / `thread_ts`（permalink の `?thread_ts=` から取れる）/ 本文 を拾う。

### Step 3: 会話単位に畳む
`key = channel_id + ":" + (thread_ts || "root")` でグルーピングする。

**例外: チャンネル直下（root）で、別々の相手に別々の依頼を投げている場合は分ける。**
`key = channel_id + ":root:" + メンション相手` とする。同じチャンネルの直下に
「@Aさん これお願い」「@Bさん こっちお願い」と続けて投げたとき、単純に畳むと
新しい方だけが残り、**古い方の依頼が一覧から消える**。実際に #group-mseセールスチーム で
広瀬さん宛と植松さん宛の回収依頼を2分差で投げたケースがあり、片方が落ちた。

スレッド内は分けない。スレッドは話題が1本なので、最後の発言だけ見れば足りる。

Step 2 は**新しい順**なので、各 key で**最初に出てきた1件が、その会話における自分の最終発言**。
それだけ残して以降は捨てる。これで数百件が数十会話に落ちる。

`D06S2EVR5GV`（自分専用DM）の key は全部捨てる。

### Step 4: 返信が来ているか判定
会話ごとに、自分の最終発言より後に**自分以外の人間**の発言があるかを見る。

- **スレッド内**（`thread_ts` あり）
  `slack_read_thread(channel_id, message_ts=thread_ts, oldest=自分の最終発言ts)`
- **チャンネル／DM直下**（`thread_ts` なし）
  `slack_read_channel(channel_id, oldest=自分の最終発言ts, limit=20)`

判定：
- 自分以外の発言が1件でもある → **返信済**。落とす
- 無い → **未返信候補**。残す
- botのみが反応している → 未返信候補のまま残す（botは返事ではない）

### Step 5: スタンプの有無で2つに分ける
未返信候補それぞれについて `slack_get_reactions(channel_id, message_ts)` を引き、
**自分の最終発言にリアクションが付いているか**を見る。これが一覧の一次区分になる。

| 区分 | 状態 | 意味 |
|---|---|---|
| **A. 未読疑い** | リアクションなし・返信なし | 押されてすらいない。気づかれていない可能性がある |
| **B. 既読スルー** | リアクションのみ・返信なし | 見てはいる。文字の答えが返っていない |

**スタンプが付いていても落とさない。** `:承知:` `:済:` `:確認します:` が付いていても、
それは「見た」「やる」の表明であって、**質問への回答にはなっていない**。
「アカウントは併用できますか？」に `:確認します:` が付いた状態は、答えを待っている状態のまま。

ただし B の中でも `:済:` `:done:` `:対応済:` のような**完了を表すスタンプ**が付いたものは、
依頼が片付いている可能性が高い。行末に `（済スタンプ）` と添えて、催促の要否を人が判断できるようにする。

A を先に、B を後に出す。**催促して効くのは A** で、B は相手が抱えている状態だから。

### Step 6: 優先度をつける
本文から、そもそも返事を期待している発言かを判定する。

まず **返事を期待している発言かどうか**で絞る。

- **拾う** … 他者メンション `<@U…>` を含む、または 依頼・質問（`？` `?` / お願い / 確認 / いただけ / ご対応 / 回答 / どう / いつ / できま / 可能 / 教えて）を含む
- **低（拾わない）** … 相槌・完了報告のみ（了解 / ありがとう / 承知 / すみません / はい / OK など短文）、宛先のない独り言、共有だけの投稿

拾ったものに、**放置時間で**バンドを付ける：

| バンド | 放置時間 |
|---|---|
| 🔴 | 24時間以上 |
| 🟠 | 8〜24時間 |
| 🟡 | 8時間未満 |

週明けは週末を挟んでも24時間に届かない案件が多く、24時間だけを境にすると全件が同じ色になって
一覧が平坦になる。8時間の段を入れるのは「その日のうちに動くべきもの」を浮かせるため。

**低は既定では出さない。** 件数だけ「他N件（相槌・共有のみ）」と添える。
ここを甘くすると一覧がノイズで埋まり、誰も見なくなる。

### Step 7: 放置時間を出す
**放置時間 = 実行時刻 − 自分の最終発言の時刻。** これが一覧の主役なので、必ず全件に付ける。

表記は桁を落とさず、ひと目で深刻度が分かる形にする：

| 経過 | 表記 | 例 |
|---|---|---|
| 24時間以上 | `N日M時間` | `2日3時間` |
| 1〜24時間 | `N時間M分` | `5時間20分` |
| 1時間未満 | `N分` | `42分` |

「1日前」「昨日」のような丸めは使わない。`2日3時間` と `2日20時間` では催促の緊急度が違う。

### Step 8: 出力
**A（未読疑い）→ B（既読スルー）の順**に2ブロックで出し、各ブロック内は**放置時間の長い順**。

```
*🔇 押されてすらない（未読疑い） 11件*

🟠 12時間45分 | #zcom載せ替え | → 木村さん
   末次さんに一度、この値付けで進めてよいかアグリ取ってもらえますか？？
   {permalink}

*👀 スタンプだけ返ってきている（既読スルー） 11件*

🟠 14時間23分 | #makeshop-btob-お問い合わせ | → 竹内さん :承知:
   過去のBtoBオプション提案ショップっぽいので意図を聞いてみてください
   {permalink}
```

- 行頭の絵文字は放置時間バンド（🔴24h+ / 🟠8h+ / 🟡8h未満）
- `→` の後ろはメンションした相手。メンション無しなら `→ （宛先なし）`
- B では相手名の後ろに**押されたスタンプ名**をそのまま出す（`:承知:` `:済:` など）
- 2行目は本文冒頭60字

末尾に `— 対象: {AFTER}〜{TODAY} / 全{X}会話を確認 / 未返信{Y}件（未読疑い{a} / 既読スルー{b}） / 返信済{c}件・相槌や共有のみ{d}件は省略`

### Step 9: Slack DMに投稿
**この一覧はSlack DMで届けるのが既定の届け方。** 会話の中で結果を表示した場合も、
特に「投稿しなくていい」と言われていない限り投稿まで行う。

```
slack_send_message(channel_id = "D06S2EVR5GV", message = 上記の一覧)
```

引数は `text` ではなく **`message`**。`text` で呼ぶと `no_text` エラーで送信されない。
また **1メッセージ5000文字まで**。超えるときはバンド単位で分割して複数回送る
（🟠以上で1通、🟡で1通、のように。1件を途中で切らない）。

**未返信が0件のときは投稿しない。** 「0件でした」を毎日2回受け取ると通知として機能しなくなる。
会話の中で聞かれたときは0件でもそのまま「0件」と答えてよい。

## 判断を誤りやすい点

- **降順の最初＝最終発言**。これを取り違えて古い発言で判定すると、返信済のものを未返信として出してしまう
- **`thread_ts` はスレッド親のts**。自分の発言のtsと混同しない。`slack_read_thread` に渡すのは親のts、`oldest` に渡すのが自分の発言のts
- **チャンネル直下の判定は「自分より後に誰か喋ったか」**であり、その発言が自分への返事かどうかまでは機械的に分からない。賑やかなチャンネルでは「別の話題が流れただけ」で返信済と誤判定しうる。他者メンション付きの発言については、流れた発言が本当に応答か本文を読んで確かめる
- **自分専用DM `D06S2EVR5GV` の除外**を忘れると、毎回メモが全部「未返信」として並ぶ
- 期間を伸ばすほど精度は落ちない代わりにAPI呼び出しが増える。3日が既定
