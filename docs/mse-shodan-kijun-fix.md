## 2. 原因（7件。すべて数式レベルで確認済み）

### 原因1（本丸）受注列と検収列が同じ表にあるのに、日付軸がシートに1つしかない

`商材区分別!I5`（**受注**売上）と `商材区分別!M5`（**検収**売上）の実物：

```
I5 (受注売上) =IF($D$2="作成日",SUMIFS(明細!$J:$J, 明細!$V:$V,"○", 明細!$AG:$AG,$A5, 明細!$X:$X,"受注到達", 明細!$AM:$AM,…),
               IF($D$2="受注日",SUMIFS(… 明細!$X:$X,"受注到達", 明細!$AR:$AR,…),
                                SUMIFS(… 明細!$X:$X,"受注到達", 明細!$AU:$AU,…)))

M5 (検収売上) =IF($D$2="作成日",SUMIFS(明細!$J:$J, 明細!$V:$V,"○", 明細!$AG:$AG,$A5, 明細!$Z:$Z,"○",     明細!$AM:$AM,…),
               IF($D$2="受注日",SUMIFS(… 明細!$Z:$Z,"○",     明細!$AR:$AR,…),
                                SUMIFS(… 明細!$Z:$Z,"○",     明細!$AU:$AU,…)))
```

**M列（検収売上）の「受注日」分岐が `$AR`（受注月）で絞っている。**
状態の条件（`$Z="○"` ＝検収到達）だけが検収で、月は受注月。ここが不整合の中心。

| 選んでいる基準 | 受注売上の中身 | 検収売上の中身 |
|---|---|---|
| 作成日 | ❌ その月に作成した案件の受注額 | ❌ その月に作成した案件の検収額 |
| 受注日 | ✅ その月の受注額 | ❌ その月に**受注**した案件のうち検収済みの額 |
| 検収日 | ❌ その月に**検収**した案件の受注額 | ✅ その月の計上額 |

**どの基準を選んでも、4列のうち半分は列名と中身が食い違う。**

実データ（2026-09-11 時点のシートそのまま／明細から再計算して一致を確認）:

- `商材区分別`（2026-09 / 受注日）… 受注売上 **5,748,450** ／ 検収売上 **60,000**
- `経由メモ別`（2026-09 / 検収日）… 受注売上 **5,536,000** ／ 検収売上 **1,465,000**

**同じ2026年9月の「受注売上」が、シートによって 5,748,450 と 5,536,000。**

### 原因2 シートごとに期間・基準が独立していて、いまバラバラ

| シート | 期間 | 基準 | 対象件数 |
|---|---|---|---|
| 商品別 | 全期間 | 作成日 | 437 / 437 |
| 商材区分別 | 2026-09 | 受注日 | 37 / 437 |
| 経由別 | 2026-07 | 受注日 | 25 / 437 |
| 担当別 | 2026-06 | 受注日 | 32 / 437 |

| 外注先別 | 全期間 | 作成日 | 437 / 437 |

使い方ガイドの「クロスフット: …合計はすべて一致する（**同じ期間・基準のとき**）」という前提が崩れている。

### 原因3 `対象件数`（G2）の分岐が2つしかなく、基準＝検収日のとき受注月を見る

```
G2 =IF($D$2="作成日", COUNTIFS(…明細!$AM:$AM,…), COUNTIFS(…明細!$AR:$AR,…)) & " / " & … & " 件"
```

本体の行は3分岐（AM/AR/AU）なのに、G2だけ2分岐。**基準＝検収日を選ぶと、
見出しの対象件数は受注月で数え、表の中身は検収月で数える**という状態になる。

これが `経由メモ別`（2026-09 / 検収日）で対象件数 **37**・合計 **35** とずれていた正体。
明細から再計算: 受注月=2026-09 が **37件**、検収月=2026-09 が **35件**。
行が抜けていたのではなく、見出しの数え方が違っていた。

> 2026-09-12 時点の本書では、このズレを「経由メモ別のフォールバック行に `経由：運営代行` が無い
> せいではないか」と推定していた。**その推定は誤り**。数式を直接確認して原因3が真因と判明した。

### 原因4 「全期間」の件数が基準によって変わる

期間＝全期間のとき、条件は `IF($B$2="全期間","*",$B$2)` になる。
COUNTIFS の `"*"` は**空欄を拾わない**ため、日付が入っていない行が基準ごとに落ちる。

| 基準 | 「全期間」の対象件数 |
|---|---|
| 作成日 | 437（作成月が空の行は0件） |
| 受注日 | 400（受注月が空の行が37件） |
| 検収日 | 400 ← G2はARを見る（原因3）。表の中身は375 |

### 原因5 `担当_XX` の対象件数が担当で絞られていない

`担当_広瀬!G2` の数式に `明細!$S`（担当）の条件が無く、全担当の件数が出ている。
2026-07 / 受注日 で表示 **25件**、広瀬本人は **7件**。

### 原因6 `担当_XX` の4行目ヘッダが中身と対応していない

4行目は `作成件数 / 受注到達 / ロスト / オープン / 不明 / 受注率 / 決着率 / 受注売上 …` だが、
実際の表は6行目以降で `売上 / 粗利 / 件数 / 粗利率`。`担当別` シートのテンプレートの残骸。

### 原因7 `担当_XX` にロスト・ペンディングの行が無い

確度別の行は 到達 / A / B / C / D の5行のみ。
広瀬の 2026-07（受注月）では **4件・4,812,200円** がどの行にも入らず、表から消えている。

### 前提（仕様。案A・案Cいずれでも直らない）母集団が「2026年に作成された商談」

SFレポート「GAS用_mse商品分析」は作成日 2026/01/01〜12/31 で抽出しており、
2025年作成・2026年計上の案件は最初から入らない。
`MSE_26MM計上予定` や 業績管理 の計上額とは**構造上一致しない**（ガイドに明記済み）。

なお3行目の注記にある「受注日が2026年外の**42件**」も実数と違う。
明細では 受注月が2026年外 **53件**（うち受注到達0件）、検収月が2026年外 **106件**（うち検収到達0件）。
**受注到達・検収到達の行はすべて2026年内**なので、金額には影響しない。注記の数字だけ直す。

## 3. 直し方（採用：案C「D2単軸」）

### 3-0. 案Aからの変更点

案A（件数＝作成月／受注金額＝受注月／検収金額＝検収月 を1枚に並べる）は**撤回**。
理由は井上さんの指示「計上と受注で横並びにしてもらってたけど、やめて。D2で絞り込んだ物事に出して」。

| | 案A（撤回） | 案C（採用） |
|---|---|---|
| D2「基準」 | 撤去する | **残す。これが唯一の軸** |
| 受注列と検収列 | 1枚に並べる（軸だけ分ける） | **並べない。選んだ軸のぶんだけ出す** |
| 1画面で受注と計上の比較 | できる | できない（D2を切り替える） |
| 列名と中身の食い違い | 起きない | 起きない |

案Cは「1シート＝1レンズ」。混ざる余地が構造的に無くなるぶん、案Aより単純で誤読しにくい。

### 3-1. 適用範囲

**全シートに適用する**（井上さんの指示は `担当_広瀬` を見ての発言だが、
「D2で絞り込んだものを出す」は一般則として読める。`担当_XX` だけに留めたい場合は要連絡）。

- 主集計: `商品別` `商材区分別` `経由別` `担当別` `経由メモ別` `外注先別`
- 担当個人: `担当_広瀬` `担当_植松` `担当_井上` `担当_小菅` `担当_吉牟田`

### 3-2. D2 と各シートの対応

`PERIOD` ＝ `IF($B$2="全期間","*",$B$2)`。範囲はすべて `$2:$5000`。

| D2 | 月列 | 到達行のラベル | 到達の条件 | 意味 |
|---|---|---|---|---|
| 作成日 | `$AM` | 受注済み | `$X="受注到達"` | その月に作成された商談 |
| 受注日 | `$AR` | **受注済み** | `$X="受注到達"` | **その月に受注した案件** |
| 検収日 | `$AU` | **計上済み** | `$Z="○"` | その月に計上した案件 |

**1つの数式の中で月列と到達条件がねじれないこと**が仕様の核。
現行の `M列（検収売上）` は 到達条件が検収・月列が受注 になっており、これが原因1。

### 3-3. 主集計シートの変更（`商材区分別` 5行目を例に）

金額列を「受注4列＋検収4列」の8列から、**`売上 / 原価 / 粗利 / 粗利率` の4列**に集約する。

| セル | After |
|---|---|
| `G2` 対象件数 | `$D$2` を3分岐にして `AM`/`AR`/`AU` を切り替え（現在は2分岐＝原因3） |
| `B5` 対象件数 | `=COUNTIFS(明細!$V:$V,"○",明細!$AG:$AG,$A5, 明細!<月列>,PERIOD)` |
| `C5` 到達 | 上に `明細!$X:$X,"受注到達"`（検収日のときは `明細!$Z:$Z,"○"`）を追加 |
| `D5` ロスト / `E5` オープン | 上に `明細!$X:$X,"ロスト"` / `"オープン"` を追加 |
| `I5` 売上 | `=SUMIFS(明細!$J:$J, 明細!$V:$V,"○", 明細!$AG:$AG,$A5, <到達条件>, 明細!<月列>,PERIOD)` |
| `J5` 原価 | 同上、合計元を `明細!$M:$M` |
| `M5〜P5`（旧 検収4列） | **削除** |
| `Q5` 見込 | `=SUMIFS(明細!$AC:$AC, 明細!$V:$V,"○", 明細!$AG:$AG,$A5, 明細!<月列>,PERIOD)` |
| `S5` LT中央値 | 現状どおり `$D$2` を使う（`_LT` は3基準ぶん持っているのでそのまま動く） |

`F5`(`=B5-C5-D5-E5`) `G5` `H5` `K5` `L5` `R5` は**変更不要**（セル参照のみ）。

**受注率・決着率の扱い**: 分母が「その月に受注日がある件数」になると構造上ほぼ100%に張り付き
意味を持たない。**`$D$2="作成日"` のときだけ値を出し、他の基準では空欄**にする。

### 3-4. 3行目の注記（差し替え文）

> D2の基準で選んだ1軸だけで集計しています。受注日＝その月に受注した案件、
> 検収日＝その月に計上した案件、作成日＝その月に作成された商談。
> 受注率・決着率は作成日基準のときだけ出ます。
> 母集団は2026年に作成された商談のみ。業績管理・SFの計上額とは母集団が違うため一致しません。

### 3-5. コード側の変更点

1. `base3_()` は**残す**（案Cでは D2 が正式な軸なので3分岐は正しい）。
   ただし「到達条件」も同じ分岐で切り替わるよう `cnt_` / `sum_` を直す。
   今は月列だけが分岐し、到達条件（`$X="受注到達"` / `$Z="○"`）が固定なのがバグ。
2. `G2`（対象件数）の2分岐を3分岐にする（原因3）。
3. 主集計シートの検収4列（`M〜P`）を削除し、受注4列を `売上/原価/粗利/粗利率` に改名。
   `writeGrid_` の列数・ヘッダ定義を同時に直す。
4. 受注率・決着率は `IF($D$2="作成日", …, "")` で包む。
5. 3行目の注記を 3-4 に差し替え。列見出しも `売上`・`粗利` に統一。
6. `担当_XX` は 3-6 のとおり作り直す。
7. 使い方ガイドの「■ 数字の読み方（注意）」の
   「受注月・検収月は集計シートからは使っていない」（v2.0時点で既に事実と違う）と
   「クロスフット」の記述を更新する。
8. `_LT`（13期間×3基準＝39列）は**触らない**。案CではD2が生きるのでそのまま使える。

### 3-6. `担当_XX` シート（5枚）— ここが今回の指摘の直接の対象

現状の作りを実物の数式で確認した結果、**D2がほとんど効いていない**。

| 部位 | 現状 | 問題 |
|---|---|---|
| 左ブロック `A5:E12` 【計上：検収月】 | `$AU` **ハードコード** | D2を検収日以外にしても変わらない |
| 右ブロック `G5:K12` 【受注：受注月】 | `$AR` **ハードコード** | 同上 |
| `G2` 対象件数 | D2で分岐するが**担当で絞っていない** | 広瀬のシートに全担当の件数が出る（原因5） |
| `U列` 案件一覧（QUERY） | D2で `AM`/`AR`/`AU` を切り替え | ここだけ正しくD2に追従している |
| 4行目のヘッダ | `作成件数/受注到達/…/検収粗利率/見込/受注平均単価` | **中身と全く対応していない残骸**（原因6） |
| 確度別の行 | 到達 / A / B / C / D | **ロスト・ペンディングの行が無い**（原因7） |

**After（案C）**: 左右2ブロックを廃止し、**D2に従う1ブロックだけ**にする。

```
A5  ■ 確度別
A6  (空) | B6 売上 | C6 粗利 | D6 件数 | E6 粗利率
A7  受注済み ← D2=検収日 のときは「計上済み」
A8  内示（A） / A9 提案中（B） / A10 案件化（C） / A11 リード（D）
A12 ロスト・ペンディング   ← 新設（原因7）
A13 合計
```

各セルは `SUMIFS(明細!$J:$J, 明細!$V:$V,"○", 明細!$S:$S,"<担当名>", 明細!<月列>,PERIOD, <行の条件>)`。
`<行の条件>` は 到達行が `$X="受注到達"`（検収日のときは `$Z="○"`）、A〜D・ロストは `$G="<進捗状況の原文>"`。

同じ構造を `■ 大カテゴリ` `■ 小カテゴリ` `■ 経由メモ別` にも適用し、いずれも左右ではなく1ブロックにする。

`G2` は担当名の条件を追加する:
`=COUNTIFS(明細!$V:$V,"○", 明細!$S:$S,"<担当名>", 明細!<月列>,PERIOD)&" / "&COUNTIF(明細!$V:$V,"○")&" 件"`

4行目のヘッダ残骸は削除する。

## 6. 注意（実装時の事故ポイント）

mse-shodan-gas スキルの不変条件より。いずれも**エラーにならず黙って全0になる**種類の事故。

- 明細 V列の `○` は**全角**。集計数式の条件も全角。半角 `o` にすると無言で全0。
- `AK / AL / AM / AR / AU` は `setValues` より前に `setNumberFormat('@')`。
  外すと「2026-01」が日付化して COUNTIFS が無言で全0。
- 明細は47列。列を足すときは `writeDetail_` の 列数ガード／`clearContent`／`setValues` の3か所と、
  文字列書式リスト `[37, 38, 39, 44, 47]` を同時に直す。
- 既存行を書き換えるときは必ず実物を見てから（記憶で打ち直すと全角/半角・大小文字を取り違える）。
