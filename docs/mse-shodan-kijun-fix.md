## 1. 症状

集計シートをまたいで数字を突き合わせると合わない。特に「受注」と「計上（＝検収）」を
同じ表で見ようとしたときに、どちらかが必ずおかしくなる。

---

## 2. 原因

### 原因1（本丸）受注列と検収列が同じ表にあるのに、日付軸（基準）がシートに1つしかない

各集計シートの `D2`「基準」は 作成日／受注日／検収日 の3択で、`base3_()` が
`IF($D$2="作成日", …, IF($D$2="受注日", …, …))` を組み、明細の
**AM（作成月）／ AR（受注月（全案件））／ AU（検収月（全案件））** のどれか1本で
**その表の全列を**数えている。

ところが表には受注系の列（受注売上・受注原価・受注粗利・受注粗利率・受注平均単価）と
検収系の列（検収売上・検収原価・検収粗利・検収粗利率）が同居している。結果:

| いま選んでいる基準 | 受注売上の中身 | 検収売上の中身 |
|---|---|---|
| 受注日 | ✅ その月に受注した額 | ❌ **その月に受注した案件のうち、もう検収まで終わった額**（＝その月の計上額ではない） |
| 検収日 | ❌ その月に検収した案件の受注額 | ✅ その月に計上した額 |
| 作成日 | ❌ その月に作成した案件の受注額 | ❌ その月に作成した案件の検収額 |

**どの基準を選んでも、4列のうち半分は列名と中身が食い違う。**

実データでの現れ方（2026-09-11 時点のシートそのまま）:

- `商材区分別`（期間 2026-09 / 基準 受注日）… 受注売上 **5,748,450** / 検収売上 **60,000**
  → この 60,000 は「9月の計上額」ではなく「9月受注のうち検収済みの分」。
- `経由メモ別`（期間 2026-09 / 基準 検収日）… 受注売上合計 **5,536,000**
  → この 5,536,000 は「9月の受注額」ではなく「9月検収の案件の受注額」。

**同じ2026-09の「受注売上」が、シートによって 5,748,450 と 5,536,000 になる。**
これが「数字が合わない」の正体。

### 原因2 シートごとに期間・基準が独立していて、いまバラバラ

| シート | 期間 | 基準 | 対象件数 |
|---|---|---|---|
| 商品別 | 全期間 | 作成日 | 437 / 437 |
| 商材区分別 | 2026-09 | 受注日 | 37 / 437 |
| 経由別 | 2026-07 | 受注日 | 25 / 437 |
| 担当別 | 2026-06 | 受注日 | 32 / 437 |
| 経由メモ別 | 2026-09 | 検収日 | 37 / 437 |
| 外注先別 | 全期間 | 作成日 | 437 / 437 |
| リードタイム | 2026-06 | 作成日 | 47 / 437 |

使い方ガイドには「クロスフット: 商品別・商材区分別・経由別・担当別・外注先別・コホート の
合計はすべて一致する（**同じ期間・基準のとき**）」とある。その前提が今まさに崩れている。
誰かが自分の見たい月に変えると、他の人には見えないまま全員の突合が壊れる。

### 原因3 「作成件数」というラベルが基準によって嘘になる

基準＝受注日のときの「作成件数」は作成件数ではなく「受注日がその月の件数」。
そのため「受注率」も “受注月がその月の案件のうち受注到達した率” になり、構造上ほぼ100%に張り付く
（例: 担当別 2026-06/受注日 の決着率 100.0%、商材区分別 2026-09/受注日 の決着率 94.6%）。

### 原因4（前提・仕様）母集団が「2026年に作成された商談」

SFレポート「GAS用_mse商品分析」は作成日 2026/01/01〜12/31 で抽出している。
よって 2025年作成・2026年計上の案件は最初から入らない。
`MSE_26MM計上予定` や 業績管理 の計上額とは**構造上一致しない**（ガイドにも明記済み）。
案Aで直すのは原因1〜3であって、この母集団差は残る。

## 3. 直し方（採用：案A 列ごとに日付軸を固定）

### 3-1. 列と月列の対応（これが仕様の本体）

| 列 | 数える月列 | 意味 |
|---|---|---|
| 作成件数 / 受注到達 / ロスト / オープン / 不明 / 受注率 / 決着率 / 見込（勝率込） | **AM 作成月** 固定 | その月に作成された商談のパイプライン |
| 受注売上 / 受注原価 / 受注粗利 / 受注粗利率 / 受注平均単価 | **AR 受注月（全案件）** 固定 | その月に受注した額（実績＋予定） |
| 検収売上 / 検収原価 / 検収粗利 / 検収粗利率 | **AU 検収月（全案件）** 固定 | その月に計上した額（実績＋予定） |
| LT中央値(日) | **AM 作成月** 固定 | 作成月コホートのリードタイム |

これで1枚の表が「9月作成◯件 ／ 9月受注◯円 ／ 9月計上◯円」を**同時に正しく**表示する。

### 3-2. コード側の変更点

1. `base3_()` を集計シートの数式生成から外す。`cnt_` / `sum_` は列の性質に応じて
   AM / AR / AU を**直接**指定する形に載せ替える。
2. 各集計シートの `D2`「基準」プルダウンを撤去。`ensureBases_()` の適用対象を
   `リードタイム` シートのみに限定する（LTは基準を選ぶ意味が残るため）。
   - `D2` を消すと `base3_` 参照の数式が全部壊れるので、**数式の載せ替えと同時に**行う。
3. `D2` を消した集計シートの2行目は `期間` と `対象件数` だけにする。
   `対象件数` も **AM 作成月**固定でカウントする。
4. 3行目の注記を差し替える:
   > 件数・受注率・決着率は**作成月**、受注系の金額は**受注月**、検収系の金額は**検収月**で数えています。
   > 母集団は2026年に作成された商談のみ。業績管理・SFの計上額とは母集団が違うため一致しません。
5. 列見出しを明示する: `受注売上（受注月）` / `検収売上（検収月・計上）` など。
6. `_LT`（13期間×3基準＝39列）はそのまま触らない。参照するのは
   リードタイムシートと、各集計の LT中央値（作成日ぶん）だけになる。
7. 使い方ガイドの「■ 数字の読み方（注意）」と「クロスフット」の記述、
   および「受注月・検収月は集計シートからは使っていない」（v2.0時点で既に古い）を更新する。

### 3-3. 任意（あると読みやすい）

- `受注件数（受注月）` / `検収件数（検収月）` の2列を足す。
  いまは受注売上に対応する件数がなく、単価の妥当性が確認できない。
  → 追加する場合は `writeGrid_` の列数と、各シートのヘッダ定義を同時に直す。

### 3-4. 案Aで失われるもの

「受注日基準で受注率を見る」使い方はできなくなる。ただし原因3のとおり
受注日基準の受注率は構造上ほぼ100%になり、指標として意味を持っていない。

## 6. あわせて見つかった別件（案Aとは独立）

### 6-1. `経由メモ別` の合計が対象件数より2件少ない

期間 2026-09 / 基準 検収日 で、対象件数 **37** に対し全体ブロックの合計が **35**。
2件がどの行にも入っていない。
（全体35 ＝ mse開発のみ15 ＋ mse開発以外20 で、ブロック分割の不変条件そのものは保たれている。
受注売上も 5,536,000 ＝ 2,780,000 ＋ 2,756,000 で一致。）

疑わしい点: `経由別` には `運営代行` 行があるが、`経由メモ別` のフォールバック行
（`経由：〇〇`）には **`経由：運営代行` が無い**。フォールバック行の生成元が
`_設定` F列と揃っていない可能性がある。要確認。

### 6-2. 使い方ガイドの記述が v2.0 と食い違っている

「■ 数字の読み方（注意）」の
> 受注月・検収月 | 集計シートからは使っていないが、明細をフィルタして「7月に受注した案件」を見るときに使える。

は v2.0（検収日基準の追加）で既に事実と違う。案Aの改修と同時に直す。
